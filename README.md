## ES添削ツール
生成AIを使って、就活のエントリーシートを添削するWebアプリです。
公開URL: https://es-checker-jf87khgtnj4nfg8ng38tth.streamlit.app/

## 作った背景
就活でESを書く際、自分では良し悪しを判断しづらく、第三者に見てもらうにも時間がかかるという課題がありました。
生成AIに面接官の視点で評価させることで、何度でも即座にフィードバックを得られる仕組みを作りました。

## 機能
- 設問・回答・志望業界を入力すると、5つの観点で採点
- 各観点について、評価の根拠と改善案を提示
- 改善後の文章例を自動生成
- 文字数カウント

## 使用技術
- Python 3.14
- Streamlit（UI・デプロイ）
- Google Gemini API（gemini-3.6-flash）
- Streamlit Community Cloud（ホスティング）

## プロンプト設計
### A(採点型)
最もオーソドックスな採点フィードバックの形式。
「結論の配置」「具体性」「因果関係の明確さ」「設問への適合性」「志望業界との接続」という5つの観点から、それぞれ10点満点で採点。
各項目に対して短い評価コメントと改善案を付け、最後に改善後の文章例を提示するという網羅的な添削スタイル。
### B(役割強化型)
「面接官としてこのESをどう評価し、選考結果はどうなるか」という実務的なスタイル。
冒頭で第一印象と選考結果を明言し、そのうえで判断根拠を掘り下げる。
Aよりも実践的・具体的な「選考通過可否」の視点が強い。
### C(思考手順指定型)
AIに対して「まずこうしろ、次にこうしろ」という思考プロセスそのものを手順として指定し、段階的に評価させるスタイル。
AやBと違い、評価の根拠を「事実の抽出」という客観的に分解してから点数をつけている点が最大の特徴で、採点の透明性・再現性が高く、なぜその点数になったかの論理的な追跡がしやすい。

## 工夫した点
- AI呼び出しを main.pyのreview関数、UIを app.pyに分けました。その結果、途中でAIの提供元を乗り換えたときに、app.pyを変更せずに済みました。
- ローカルは.envから、クラウドはSecretsから設定を読む必要があり、両方に対応する読み込み処理を実装しました。「ローカルで動く」と「本番で動く」が別物だと体感しました。
- セキュリティ面では、.gitignoreで .envを除外し、 git statusで毎回確認しました。実際に .envが含まれていないことを見てからpushしています。
- 原因不明のエラーに対して、repr()で変数の中身を出力しました。これで認証エラーの原因が特定できました。原因不明のエラーではまず変数の中身を目視しています。
